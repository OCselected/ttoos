# 2026-11-28  「开源之道」·论文略读：When Skills Tell Agents Not to Ask — 规则层没有编辑者

## 一句话推荐

**这篇论文最容易被读成「有些恶意 skill 在教 agent 别问」，读错了——它测出的是一个比恶意更麻烦的东西：在 153 万个 skill 里，削弱监督的指令占监督类指令的 13.3%、其中 70.1% 无条件生效；而这批指令的扩散不是被采纳者改出来的，是从极少数上游原样复制下来的。于是真正的问题不是「谁写了坏规矩」，而是规则层已经成了一个没有编辑者、没有评审、没有版本记录的公共品。**

## 内容概要

### 一、先纠正一个被摘要带偏的读法

摘要写「每 17 个 skill 有一个含放松监督指令」，这句话本身没错，但它诱导的结论是错的。论文 Table 4（人工标注，95% CI）给的是**双向**的数：

- **放松监督 13.3% [11.7, 15.0]**
- **收紧监督 36.4% [33.7, 39.2]**
- 比例 **2.7 : 1**，技能层面 5.8% vs 16.9%

也就是说，这个生态里**加护栏的行为是主流**。论文自己在 Threats 段还说明这个比值是保守的——词表漏掉收紧的比例高于漏掉放松。

那么问题在哪？**在分布，不在数量。**

### 二、不是扩散型污染，是「少数源头 × 高保真复制」

第三组数字是全文最有制度意味的一组：

- 去重口径 5.8%，按副本计 5.4%（比值 **0.94**）——**复制不放大放松**，收紧被稀释得更厉害（16.9% → 14.4%，0.85）
- **93.4% 的变体原样保留祖先的监督文本**（各规格 92–97%）
- **86,048 个不同放松单元里，960 个（1.1%）贡献了一半的放松出现次数**
- **承载放松的家族里，2.4% 贡献了一半的副本**

采纳者几乎不改。这意味着「生态在系统性教 agent 不问」这个判断**数据不支持**；准确的说法是：**生态里有大约 960 句话在起作用。**

作者的处方因此极具体，而不是号召式的：改 100 个最重的家族可覆盖近 1/4 的放松副本；人工过 960 个单元可覆盖一半。

### 三、三个机制数字

- **放松的三种手段**：权限开关 33.9% + 跳过确认 27.4% + 持续执行不中断 16.0%，合计超四分之三。
- **70.1% 无范围限定**（有 scope 的仅 29.9%）。修复成本是一行字：`pass --yes only in CI`。
- **高危能力 × 放松正相关**：执行 shell、装包、`sudo` 的 skill，在同等监督语言量下放松的 odds 是 1.7–1.8 倍，**且没有以更多收紧来补偿**（装包 0.59、sudo 0.75、`curl | sh` 0.77）。

那条唯一的反向例外比主效应更值得记：**git write 的收紧 OR 是 2.01** —— 会写版本库的 skill 反而更收敛。

→ **凡动作留下可追溯痕迹的，规则就更严格；凡动作不留痕的，规则就更松。规则密度的真实来源不是风险评估，是可追溯性。**

### 四、扫描器失效的方式：不是模型不行，是问错了问题

400 单元金标测试里：Cisco 离线 recall 0.02、加 LLM 0.15；SkillSpector 0.21 / 0.46；合并 0.51 但 precision 0.28。**23–29% 的告警落在「收紧」指令上**——把护栏当风险，因为 excessive-agency 规则对 `do not auto-approve` 与 `auto-approve` 同样开火。

同一个模型（GPT-5.4），换成论文的 codebook 提问，**F1 从 0.36 跳到 0.65**，与论文自研检测器统计上不可区分（p=1.0）。

论文这句话是判据级的：`The question asked, not the model, limits the scanners.`

## 为什么值得读

### 规范原文只写了六个字：There are no format restrictions

`agentskills.io/specification` 逐字：`The Markdown body after the frontmatter contains the skill instructions. There are no format restrictions.`

再看两个可选字段：`license` 是 **Optional**，`allowed-tools` 是 **Optional + Experimental**。

**唯一能声明权利的字段是可选的，唯一能预授权工具（即放松监督）的字段也是可选的——两个可选字段，一个管权利、一个管权力，都没有约束力。**

而承载这份规范的仓库 `agentskills/agentskills`，截至论文核验时最后推送是 2026-08-09，已静止八十多天，107 个 issue 未处理。

### 政策被写下的概率，与它可被机器检查的难度成反比

这句话在 LF Research 2026 年那份 AI 时代开源调研里量过一次：政策内容里排前两位的是「透明度披露 76%」「贡献者评审责任 76%」，而这两项恰是最不可机器检查的；可以机检的只有「许可与版权 39%」「具体工具要求 6%」。

本篇在同一方向上又走了一步：**最需要可执行的那一部分（监督指令的行为范围）连字段都没有**，所以它既写不进政策，也检不出来，只能靠上游那 960 个写作者的习惯来决定。

论文的四条处方全部是「在既有位置补一行」，没有一条需要新建机构。问题规模很大（数万个 skill 写下过放松指令），修复成本极低（960 个单元、一行 scope）。**而正因为修复这么便宜却没人做，它反过来证明了那个空位：没有人在管这一层。**

## 为什么对开源社区如此重要

### 奥斯特罗姆清单：这一层连第 1 条都不成立

把 skill 规则层当成一个共享资源系统，对照奥斯特罗姆的经典八条：

- **清晰边界**：规范里没有「适用范围」字段，70.1% 的放松指令无 scope
- **规则与当地条件相符**：恰恰相反，规则写成通用的，被携带到作者未曾设想的上下文里
- **集体选择安排**：采纳者几乎不改（93.4% 原样保留），无评审通道
- **监督**：零。扫描器抓不到，还把护栏误报为风险
- **分级制裁 / 冲突解决**：不存在，规范无强制力
- **对组织权的最低承认**：唯一能声明权利的是可选 `license`
- **嵌套层级**：格式层与行为规则层完全脱钩

→ **这不是一个「治理不善的公地」，而是一个尚未被承认为公地的公共品。**

许可证文件、CONTRIBUTING、CODE_OF_CONDUCT 之所以能撑起千万个项目，不是因为这些文本写得优美，而是因为它们在**公开、可 diff、可争论的轨道上，且有人被指定为编辑者**。skill 规则层复制的是未经审议的行为指令：没有编辑者、没有版本记录（语料只存内容与出现次数，不存规则变更史）、也没有任何人被要求读它。

### 威廉姆森：L3 是一片空白，L4 是事实上的规则作者

摊开四层：L1 是「让 agent 顺畅干活」的工程文化；L2 是 `SKILL.md` 规范、**只管格式**；L3 治理机制**空**；L4 是写 skill 的人顺手加一个 `--yes`。

一个格式标准不规定内容，是合理的设计选择。**但它把一个治理问题留在无人认领的位置上，而技术生态不会因为没人认领就不产生规则**——只会以没有作者的方式产生。

## 延伸思考

### 一、如果「少数几行被广泛复制的规则」是问题，开源本来就有一整套办法

开源世界对付这种情形的方式，从来不是写更好的规则，而是给规则一个**可 diff、可争论、可指名的文件位子**：LICENSE、CONTRIBUTING、CODE_OF_CONDUCT、SECURITY.md 之所以有效，是因为有人是它们的编辑者，改名要走 commit，修订要留理由。

所以 skill 生态缺的不是好规则，**是那个文件的位子**。

这里有个值得停一下的地方：如果 upstream first 是开源解决「同一段代码被复制一千次各自腐烂」的标准答案，那么这条原则在这个生态里是**无处落地**的——因为没有 upstream，没有维护者，只有一个内容语料库和一份只说「body 无格式限制」的格式规范。

### 二、范围条款的成本不对称，是一个可推广的诊断

一条规则的无条件生效版与条件生效版之间，成本差常常只有一行字（`--yes` 只在 CI 里用），而制度后果差一个数量级：前者改变每一次加载时的默认值，后者只改变特定上下文。

判据很简单：**任何「默认放开」的规则设计，先问一句「写条件要多少字、谁付这个字」。**

70.1% 无范围 → 这个字几乎没人写，而它是一行。这不是懒惰能解释的：一行字的成本之所以没有人付，是因为**付了没有回报，不付没有代价**。

### 三、有痕迹的动作收紧，无痕迹的动作放松

git write 的例外（收紧 OR 2.01）揭示了规则密度的真实来源：**不是风险评估，是可追溯性。** 一套规则体系里，那些「做了不留痕」的动作必然规则更松，且更难被后续审计。

这条可以直接拿去审查任何协作系统：提交规范严、部署脚本松；评审留痕严、私聊决策松；文档提交严、模型权重发放松。**凡留下痕迹处，制度可生长；凡不留下痕迹处，制度必然缺席。**

### 四、必须停在的地方

论文 §6 写得极克制：`We measure what skills say, not how agents act`（我们测的是 skill 说了什么，不是 agent 怎么行为）。词表召回也只有 32%，区间宽到 [14%, 75%]，因此所有绝对计数都是下界；第二编码者是 LLM 而非人类；只取英文、只取公开 GitHub 仓库。

**本文能支持的强命题只有一个：规制行为的那一层文本里，削弱监督的内容以高浓度、无条件、高度集中的方式存在，且无任何审核装置。** 「有数万个 skill 写着别问」推不出「有数万个 agent 不问」。任何越过这一步的转述，都是把规则文本的统计当成行为事实。

还有一条本研究未覆盖、但值得单独核验的空缺：GitSkills 覆盖 282,200 个公开仓库，中文生态（Gitee / AtomGit 侧的 skill 分发）完全不在样本内。这是一个可在未来单独回答的问题，不是可以由本篇推出的结论。

### 五、一个可执行的观察点

三个月后回看三件事，就知道这个空位有没有被认领：

1. **规范是否补上范围/监督字段**——判据：`agentskills.io/specification` 的 frontmatter 表新增字段，或 `allowed-tools` 从 Experimental 转为稳定。
2. **规范载体是否恢复活动**——判据：`agentskills/agentskills` 最后推送日期越过 2026-08-09，未处理的 issue 是否被清理。
3. **960 个单元是否有人来改**——判据：前 100 个承载家族里，是否出现**非原作者**的监督文本修订。这同时是奥斯特罗姆第 3 条（集体选择安排）的恢复信号。

第三件事是这三件里最要紧的：它问的不是「有没有人写更好的规则」，而是「**有没有一个不是原作者的人，被允许改这句话**」。

## 金句

> 真正的问题不是「谁写了坏规矩」，而是规则层已经成了一个没有编辑者、没有评审、没有版本记录的公共品——它和被千万个项目依赖的许可证、CONTRIBUTING 同属一类东西，唯独它没有任何一道制度装置。
