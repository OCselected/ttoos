## 一点推荐

先说清楚这篇论文做了什么，因为它比标题显示的更朴素、也更硬：

它只做两个动作。**第一个动作是数。** 从 ARIN（美国互联网号码注册管理机构）取得 2011 年 10 月 15 日分配给美国的 1,537.37 百万个 IPv4 地址全表，随机抽取 15,865,522 个（刚过 1%）逐一探测：是否在跑 web server，跑的是 Apache、Microsoft IIS，还是别的。结果：195,885 个（1.23%）在跑 web server；其中 44,211 个（22.57%）跑 Apache、24,222 个（12.37%）跑 IIS。外推到全美 IPv4 空间，美国约有 18,981,268 台对外可见的 web server，其中 4,284,049 台跑 Apache（§3.1）。

**第二个动作是称。** 既然 Apache 的价格是零，那就去问：如果把这些服务器全部换成一个有价格的等价物——Microsoft IIS——要花多少钱？按三个价格点计算（§3.2）：Windows 7 的 $119.99（低端，功能太少，实际不可用）、Windows Web Server 2008 的 $469（中端，功能最接近）、Windows Server 2008 R2 Datacenter 的 $2,999（高端，一台一许可）。三档相乘，得到 **5.14 亿美元至 128 亿美元，中间值约 20 亿美元**（§3.2）。

第三个数字是这篇论文真正的标题：把这 20 亿到 128 亿美元放到美国国民经济核算的分母上。2010 年美国企业软件投资 2,950 亿美元，其中「预打包软件」占 27%，据此推算预打包软件的资本存量约 1,460 亿美元。于是 **Apache 一项软件的价值，相当于这国预打包软件资本存量的 1.3% 到 8.7%**（§3.3）。

作者的自我约束在这一段写得非常干净：「两个数据都只是量级判断（ballpark）；如果有 Apache 的更换周期估计，就可以把存量翻译成服务流量，但在那之前，这就是我们能做的最好的事。」

**这篇论文给的不是一个估值故事，而是一条方法论上的分界线：一个经济体的会计系统，可以把整层生产资料记成零而不留下任何异常——因为零价被预设成了「非市场活动」。**

## 内容概要

### 一、概念：什么是「数字暗物质」

作者从天体物理学借来这个比喻（§1）：暗物质无法被直接观测，但星系转速与引力效应暴露了它的存在。经济学的对应物是那些**非货币化、实际上无上限、却作为生产投入存在**的数字商品与服务。论文给了它三个属性，写法很克制：

- 它有时像私人资产——作为生产货币化产品的投入，常规投资延长功能或推迟过时；
- 它有时像公共品——多方可以非排他地使用；
- 与前两者的关键差别：**决定其投资与使用规模的，不是市场价格**；而且即便可见，也只能被间接测量。

这三点合起来，是「混合体」（hybrid）这个词的全部含义。作者没有把它归入公共品，也没有归入私人资产——这个拒绝站队，是全文最重要的理论动作。

### 二、框架：漏记（omission）与错归（attribution）

**漏记问题**（§2.2）。标准国民经济核算盯着市场交易，并预设交易含正价格；没有特别处理时，无价活动被默认为非市场活动。作者引 Nordhaus (2006) 「近市场品」（near-market good）的概念来定位 Apache：有真实价值的产出，但没有价格。同时作者也点出与 Nordhaus 的差别——开源有一部分活动**是**可测的：第三方咨询与独立程序员的配套服务、企业为安装运维与定制雇人、为部署购买的硬件。这些都以营运支出（operating expense）出现在账上，而不是作为软件资本。也就是说：**开源的「人」在账上，「物」不在账上。**

**错归问题**（§2.3）。作者回到标准生产函数 Y = A·f(L, K, IT)，说明无价软件没有机制进入右端，于是产生三种误归：

1. **无因增长**：Apache 代码改进，用户零成本获得升级，产出增加但看不到任何投入增加，增长被归给全要素生产率 A。作者点明这类似 Syverson (2011) 所述的本地环境外部性造成的错归，「等同于把不断改善的公共品量错了」。
2. **增长归给错的投入**：用 Apache 的企业为支持新版本增加人力，产出的增长会被归给 L 的增长，而实际来源是未被计量的 IT 资本。
3. **开源与商业软件竞争导致错归**：两种企业都增加人力，但商业软件用户多了一笔可计的 IT 支出，Apache 用户没有；标准估计会把增长多归给 L、少归给 IT。

这里有个值得停下来看的推理（脚注 19）：既然 Apache 免费、人力成本若不高于商业软件、产出又等价，商业软件本该消失；但数据显示它没有消失（尤其 Microsoft 占据可观份额）。**要让这种并存成为可持续的均衡，开源的人力支出就必须高于商业软件。** 这是一个不依赖调查问卷的推断——账本自身的结构逼出来的结论。

### 三、数字：影子价值与三把尺子

- **影子价值**（§3.2）：4,284,049 台 × 三档 IIS 价格 = 5.14 亿至 128 亿美元，中间值 20 亿。
- **尺子一：销售**（§3.3）：2010 年美国企业软件销售 3,570 亿美元，其中 2,570 亿进入私人固定投资。128 亿 / 2,570 亿 ≈ 5%，但这是**存量比流量**，作者自己说「像是拿苹果比橘子」。
- **尺子二：资本存量**（§3.3）：预打包软件存量约 1,460 亿美元 → 8.7% 至 1.3%。这一把尺子作者认为更硬。
- **尺子三：它支撑的生态系统**（§3.4）：2009 年美国互联网接入收入 596 亿美元、在线广告收入约 210 亿美元（含 101 亿无线接入）；同年企业级与大型机软件收入合计 260 亿美元。20 亿至 128 亿的 Apache，摆在 260 亿的企业级软件市场旁边「看起来相当大」——但作者立刻补一句：这仍然是存量比年销售额，不精确。

### 四、回报率与那句自我约束

作者把 Apache 放进成本收益框架（§3.5）。成本侧：NSF 在 1985–1995 年间投入约 2 亿美元建设互联网相关技术（含骨干网、运营与超算中心，NCSA 是其中之一）；DARPA 的 IPTO 在 1963–1986 全生命周期的总支出不超过约 5 亿美元，作者保守地再加 2 亿，凑出 **4 亿美元的互联网创建成本**。收益侧：把 Apache 在 1995 年之后产生的收益按 10% 折现率折回，算出至 2012 年底相当于 26 亿至 45 亿美元的经济活动。**在 4 亿美元投入上，回报率在 10.5% 至 14% 之间**（第二种算法给出 10.5% 至 19%）。

紧接着是一句在同类论文里罕见的话：

> 「没有读者应当把 Apache 的回报率精确引用为 10–14%。」

**作者在给出数字的同时，收走了引用的许可。** 这一句不是谦辞，它精确划定了这篇论文的证据类型：这是量级证据，不是参数估计。

## 一句话推荐

> 这篇论文证明了一件比「开源很值钱」更要紧的事：**国民账户把一整层生产资料记成零，却没有任何异常报警——因为零价被制度性地预设为「非市场」。**

## 为什么值得读

**它是「开源是不可见的公共投入」这个直觉的第一份可复算的操作化。** 在它之前，关于开源经济价值的讨论主要靠两类东西：一类是劳动力成本重估（如脚注 6 提到的 Ghosh et al. 2006，用重写全部开源代码所需的人力成本来估算），另一类是平台自身的统计。这篇走的是第三条路——**替换成本法**：不问「生产它花了多少」，问「如果没有它，市场要我付多少」。这两条路给出的是完全不同性质的数字：前者是投入侧，后者是用户面对的市场约束。

**它的数据是自己造的，而不是买来的。** 作者明说：最好的数据是私有目的收集的、严密看管的（Netcraft, 2012）、根本不公开供研究者做统计审查。所以他们自己扫了 1% 的 IPv4 空间。这是 2014 年，一个经济学论文自己去写扫描器——这件事本身就是方法论宣言：**当测量基础设施不向公众开放时，公共知识的生产者只能自己造尺子。**

**它的估计方向是保守的，而且保守的理由被逐条列出。** 只算对外可见的服务器（内网、私用、负载均衡后面的多实例全部漏掉）；价格用的是现行 IIS 价格而不是无 Apache 时的反事实价格（作者承认若无 Apache，IIS 价格可能更高）；GDP 口径只用边际估值、不用消费者剩余；Apache 还 disproportionately 承载访问量最大的站点（当时百万最繁忙站点中 57% 跑 Apache，第二名 nginx 15%），所以其实际功能更接近高端的 Datacenter 版本。**四个理由都指同一个方向：真实值应当偏向区间上端。** 而「偏向区间上端」这句话本身是可被检验的，不是修辞。

**它的历史叙述里有一个几乎被忽略的制度细节。** §2.1 讲：伊利诺伊大学把 Mosaic 浏览器授权出去挣了数百万美元，但 HTTPd 服务器软件的授权没有类似的运气——部分原因是它先以共享软件形式发布，源码对任何人无限制开放。主程序员 Robert McCool 等人 1994 年中离开去 Netscape 之后，webmasters 失去了协调者；到 1995 年初，市面上有八个各自改进过一部分的版本在广泛使用；这八支团队决定合并努力，合并体被称为 Apache（据说是「a patchy web server」的双关），并逐渐采纳了开源实践。

**同一年、同一所大学、同一批人，两条路：一条卖了数百万美元授权费，一条以无价的方式扩散成了整个互联网的地基。** 这两条路的差别不在技术，在「有没有一纸排他性许可」。而国民经济核算只认得前者。

## 为什么对开源社区如此重要

从「开源之道」的制度视角看，这篇论文的价值不在 20 亿还是 128 亿，而在它把一件长期只能被当作立场的事情，变成了一个可以被指认的会计事实。以下四层，是我读下来的桥接。

**第一层：这不是估值问题，是产权界面问题。** 国民经济核算是一套产权登记装置：它记录的是「谁付了钱、买了什么、记在谁的资产下」。开源在这个界面上的特征是**有使用、有投入、无交易**——于是它在资产侧是零，在产出侧贡献了增长，而增长被记进全要素生产率这个残余项 A 里。这意味着：**开源贡献在经济学的记账体系里没有被「低估」，而是被记到了另一个科目上。** 差别很重要——低估是可以修正的误差，记错科目是结构性的分类错误。作者自己的话是「omission and attribution errors are possible, even likely」——漏记与错归，正是分类问题的两种形态。

**第二层：这给「开源是俱乐部品而非公共品」提供了会计侧的支撑，而且是反直觉的那种。** 论文明确说数字暗物质是「公共品与私人投资的混合体」（hybrids of public goods and private investments），并且**拒绝**把它归入任何一边。这个拒绝在制度分析上极其重要：如果开源是纯公共品，那它的供给不足可以用公共支出补足；如果它是纯私人资产，那就由市场定价。而它是混合体——**使用上非排他、维持上要人付钱**，所以它在任何一侧的账上都不成立。这正是一个俱乐部品的会计形态：准入规则清晰（许可证），维持成本由内部人承担（维护者与企业的配套支出），而外部性（对整条互联网商业的支撑）照惯例不计价。

**第三层：它把「度量权」问题提前了十年。** 这篇论文里有一句不起眼但极重的话：最好的服务器数据「为私人目的而收集、被严密看管、不供研究者做统计审查」。作者是靠自建扫描绕过去的。把这句话搬到今天：**任何关于开源贡献规模、活跃度、健康度的权威数字，都来自某个平台的私有采集口径。** 而口径制定权在平台手上，不在研究者、也不在社区手上。2014 年这个问题还能靠「自己扫一遍」解决，因为在 2014 年，对外可见的服务器是一个物理上可枚举的对象；今天要枚举的是模型权重、依赖关系、贡献意图——这些都不再是扫描器能解决的问题。**这篇论文最锋利的地方，是它顺手证明了那条自救路径的存在条件有多苛刻。**

**第四层：它给「行政式开源」的账本表演一个确切的机制命名。** 如果一个经济体的会计系统只认有价格的交易，那么它对开源的任何「计量」都只能在两个地方落地：一是投入侧（数钱、数人、数项目），二是产出侧（数下载、数排名、数认证）。中间那一层——**使用中的价值**——在结构上不可见。于是行政动员式的开源评价必然滑向可计数的表层：因为唯一能进账本的东西，恰好是能被组织出来的东西。这不是执行者的道德问题，是**会计装置的可测性梯度**问题：能被计量的部分会被优先治理（这一点在我们此前读过的 2026 State of OSPOs 报告里已经被量化过一次——OSPO 的职责正在从「做开源的人」变成「数开源的人」）。

由此还有一个对中国语境的推论，我标注为**推论，不是作者观点**：开源在中国的行政化评价体系里被反复要求「可见的成绩」，而这篇论文说明，开源最重要的那部分价值在标准会计框架下本来就不可见。**当一套评价体系只能看见可计价的部分时，它会系统性地生产出可计价但不产生公共性的东西。** 这就是制度剧场（institutional theater）在会计层的完整机制——不需要有人作假，只需要一套只认价格的尺子。

**最后一层，关于这份测量的边界。** 作者把 Apache 单独拎出来做，明确说这只是「一个具体例子」，但同时主张：考虑到 Linux、TCP/IP 生态、World Wide Web、Perl、PHP、Firefox、以及维基百科这样的非营利 CC 授权内容，「其中几项相加，很可能达到预打包软件资本存量的相当比例，进而对美国 GDP 总量产生显著影响」。这里的措辞很谨慎——「likely」，不是「证明」。而它之所以只能「likely」，是因为每一项都需要重复一次自带扫描器的工作量。**这就是数字暗物质研究在方法论上的天花板：它只能一件一件地称，而公地的价值在结构上是清单式的、无法一次称完的。**

## 一段自我约束：这篇论文做到了什么程度

在「可复算性」这件事上，这篇论文给出了一个值得记住的分级样本：

**它可以被完整重述。** 论文的每一个数字都可追溯到四步：ARIN 地址表 + 随机抽样（15,865,522）+ 端口探测 + 三档价格乘法。没有黑箱模型，没有不可公开的微观数据。任何人拿到同一份 ARIN 快照与同一份微软价目表，都能算出同样的 5.14 亿与 128 亿。

**但它不可被重新获得。** 2011 年 10 月 15 日的 IPv4 分配快照、当时的 Microsoft 价目页、当时的探测结果，都已经不在原址。这不是作者的过失——是这类实证研究的普遍境况：**不是数据被隐藏，是数据会过期。** 这一点值得和我们在 10-20、10-21、10-23 几篇里讨论过的「复算判据」连读：这篇论文落在「可复算但不可复现」的位置上——它允许你检查它的算术，但不允许你重做它的观测。

而作者对此的处理方式，是我认为全文最值得学的地方：他们**在给出回报率的同时明确禁止精确引用**，并在结论里把「omission biases are significant, but the attribution biases are not」这句分判写清楚——漏记是显著的，错归是不显著的。他们没有把两件事一起夸大。

## 关联阅读

## 延伸思考

**追问一：数字暗物质如果被认真计量，会不会反过来伤害它？** 这篇论文的隐含政策指向是：既然开源的价值被漏记，那就应当补记，以便公共投入获得应有的回报评估。这个指向在财政说服力上是有用的。但补记需要什么？需要把使用变成可观测——许可证扫描、依赖分析、SBOM、使用遥测。而我们在 10-23 那篇里已经看到这件事的另一面：**为了让义务可核查而建立的观测层，正在变成新的治理负担。** 那么，为了让公地的价值可见而建立的观测层，会不会同样改变公地的性质？一篇 2014 年的论文无意中提出了 2026 年的问题：**被计量是一种承认，也是一种收编。**

**追问二：如果 Apache 的价值是「被替换的成本」，那它的稳定性依赖什么？** 影子价值法预设了一个可用的替代品（IIS）。这个预设今天已经松动：若某个类别里不存在功能等价的有价格商品，替换成本法就没有分母。这提示一个尚未被系统研究的问题：**开源在不同的技术栈位置上，被计量的可能性是不同的。** 有商业等价物的领域（web server、数据库、办公套件）可以被称重；没有商业等价物的领域（包管理器、构建工具、CI 基础设施、标准实现）在方法上就连称都称不了。这意味着**数字暗物质的可见性本身在技术栈上分布不均**——最底层的那些东西，恰恰是最不可被计量、也最容易被当作理所当然的。

**追问三：剩下那 77.43% 是什么？** 抽样中 195,885 台 web server 里，Apache 占 22.57%、IIS 占 12.37%，两者合计 34.94%；剩下的 65.06% 中包括无法识别标识的服务器、nginx、以及像 Google 自研内部服务器那样的私有实现（脚注 24）。整个样本里只有 1.23% 的 IP 在跑 server——98.77% 是闲置或非 web 服务的设备。这两个比例放在一起，是这份数据里最沉默的部分：**互联网的物理表面绝大部分是空的，而有人居住的那一小块里，最大的一块住的是无价软件。** 论文没有讨论这一点，但它决定了这项研究为何只能算下限。

## 金句

> 经济学家需要给数字经济里那些标准工具无法计量的构件一个名字。数字暗物质，可以是这些非货币化、实际上无上限、并作为生产投入的数字商品与服务的名字。它们是公共品与私人投资的混合体。

> 常态的经济核算把 Apache 作为生产的投入或资本存量漏掉了。常态的经济计量只盯着市场上的交易，并预设交易含正价格。没有特别的关注，常态程序就会把无价活动预设成非市场活动。总之，和其他开源软件一样，Apache 的价格与收入都是零。

> 一旦开源的使用没有具体的货币度量，就没有机制让它作为投入变量进入方程的右端。

> 比起它所帮助产生的收入，20 亿至 128 亿美元的 Apache 软件显得相当可观。

> 我们发现了漏记偏差显著的证据，但错归偏差并不显著。

> 没有读者应当把 Apache 的回报率精确引用为 10–14%。
