# 2026-10-16  「开源之道」·荐书：《信任与权力》— Niklas Luhmann

| 字段 | 内容 |
|------|------|
| **书名** | 《信任与权力：社会秩序的基本形式》 / *Vermögen und Macht* / *Trust and Power* |
| **作者** | Niklas Luhmann（尼克拉斯·卢曼，1927–1998），德国社会学家，系统论社会学奠基人 |
| **初版** | 1973（德文原版，Luchterhand，法兰克福）；英译本 1979（Bedminster Press） |

## 内容概要

Luhmann 在本书中提出了社会学史上最激进的信任理论：**信任不是一种心理状态、不是一种道德美德、不是"人对人的善意"，而是社会系统为应对复杂性而演化出来的功能性简化机制**。

面对一个由无数他人、无数事件、无数不可预测因素组成的社会，任何行动者都不可能掌握全部信息。信任就是**在信息不充分的情况下做出承诺的社会机制**——它把无法消化的复杂性"折叠"成一个可以行动的心理姿态："我信任，所以我继续"。没有这个机制，社会系统将陷入决策瘫痪。

本书的核心命题直击一切"行政动员式"安排：**信任与服从在系统论的运作逻辑上根本不兼容**。信任是行动者对风险的自觉承担——正因为存在风险，信任才有意义；而服从是风险被转移给命令者之后的姿态，服从者不承担风险，也就没有信任。**"被命令去信任"是一个逻辑悖论——它把信任降级为服从，因此不再是信任**。

对开源这个领域的意义是直接的：开源协作最深的资产不是代码，是贡献者之间**不需要外部强制就自发产生的信任**。任何试图用行政命令去"管理信任"的行为，都在系统论意义上自动消解了信任本身——它把社区里原本存在的自组织信任降格为执行命令的服从，一旦降格完成，信任就死掉了。

## 一句话推荐

**"被命令去信任的信任，已经不再是信任"** —— Luhmann 用一句话就击中行政动员式开源在系统论层面的根本不可能性。

## 为什么值得读

- 它是**信任思想谱系的系统论原点**——Coleman 讲信任是社会资本的副产品、Ostrom 讲信任来自反复互动、Hayek 讲信任是文化演化的产物、Sztompka 讲信任必须被赢得——这五位都在回答"信任从哪里来"，Luhmann 更早一步：**他回答了"信任是什么"**
- 它是「信任不能用行政命令生产」命题最锋利的系统论背书——大分流 2.0 命题在系统论层面找到了它的直接来源
- 它为「开源俱乐部品非公共品」命题补上系统论基础——**开源俱乐部的门槛不是"谁能进"，而是"谁能承担信任的风险"**
- 它给「生态是结果不是手段」补上更深的机制诊断——**信任无法被设计，只能被"简化"，被"承担"，被"赢得"**
- 它是 Luhmann 一生学术生涯的起点——后来的**系统论社会学、法律系统理论、宗教社会学、组织理论**都从这里展开

## 为什么对开源社区如此重要？

### 1. 行政动员在系统论层面的根本不兼容

大分流 2.0 命题过去一直在**制度经济学**框架内运作——Coase 的交易成本、Williamson 的治理机制、Ostrom 的公地治理原则。这些框架都指向同一个结论：行政动员式开源无法产生真开源。但过去的解释都还停留在"制度设计不对"或"激励结构不匹配"的层面。

Luhmann 给出的诊断**更根本**：行政动员与信任不兼容，不是因为"设计错了"，是因为**信任与服从在系统论的运作逻辑上就不可能共存**。这不是"设计力度不够"或"设计路径不对"，是**结构性的不兼容**——你不能通过重新设计行政动员来让它产生信任，因为信任的机制本身就与"命令"的机制互斥。

用适兕的框架说：**行政动员可以造出代码，可以造出贡献数，可以造出项目数，但它造不出信任**——不是它不够努力，是它试图做的事在系统论意义上不可能。

### 2. "信任是复杂性的简化机制" × 开源协作

Luhmann 的第二个洞见：信任之所以必要，是因为**社会系统太复杂，任何行动者都不可能掌握全部信息**。开源协作正是这个复杂性问题的极端样本：

- 一个新人加入 Linux 内核项目，他要"信任"哪些事？他要相信维护者不会恶意修改代码、相信其他贡献者的测试是认真的、相信 review 流程会公正、相信社区有共同的规范……每一件都涉及不完全信息
- 一个开源基金会接受捐赠，它要"信任"哪些事？它要相信捐赠者的意图是善意的、相信项目团队有能力管理这笔钱、相信项目章程能够约束滥用……
- 一个开源平台（GitHub / GitLab）承载上千万仓库，它要"信任"哪些事？它要相信开发者不会滥用漏洞、相信贡献者不会恶意破坏供应链、相信许可证条款会被遵守……

**开源之所以能够运行，不是因为它有一堆严密的规则（虽然也有），而是因为它有信任机制来"简化"这些不可能全知的复杂性**。信任在这里不是"道德选择"，是**制度装置**——它是开源协作的技术条件之一。

### 3. "信任 ≠ 服从" × 行政动员式开源的病理诊断

Luhmann 的核心命题——**被命令去信任的信任，已经不再是信任**——给"行政动员式开源"提供了一个极其锋利的诊断工具：

- **"开源十四五规划"**——要求团队必须贡献开源代码，这是命令贡献，不是信任贡献
- **"KPI 化的开源贡献指标"**——把贡献数、项目数、专利数作为考核指标，是把"贡献"从信任姿态降格为"服从指标"
- **"开源必须服务于国家战略"**——把开源的公共性降格为"战略工具"，是把"信任公共性"降格为"服务国家目标"
- **"开源必须走审批流程"**——把开源的自组织降格为行政审批，是把"信任自组织"降格为"服从审批"

**每一次行政干预都在把信任降格为服从，每一次降格都在消耗开源社区里原本存在的信任存量**。这就是为什么"行政动员式开源"表面繁荣（有项目、有贡献、有指标）但**无法产生真正的开源公共性**——不是执行不力，是**它做的事情在系统论意义上把信任本身消灭掉了**。

### 4. "简化机制" × 开源治理的真正任务

Luhmann 的洞见还有一个更积极的面向：如果信任是"简化复杂性的机制"，那开源治理的真正任务是什么？不是"设计信任"（设计不出来），也不是"命令信任"（命令无效），而是**减少复杂性、让信任能够自然简化复杂性**：

- **git 历史可追溯** = 让"你写的代码是不是恶意"这个问题变得可核查，简化信任
- **fork 权利** = 让"这个版本不好我换一个"变得可能，简化信任的风险成本
- **Code Review** = 让"这段代码是否可靠"变得可集体判断，简化信任的验证成本
- **许可证文本** = 让"我能怎么用这个代码"变得明确，简化信任的规则不确定性
- **声誉机制** = 让"这个人靠不靠谱"变得可从长期观察得知，简化信任的时间成本

**开源治理的每一件具体制度装置，本质上都是一种"信任简化机制"**——不是"制造信任"，是让原本存在的信任机制能够更高效地简化复杂性。这不是"设计信任"，是**为信任的自发机制创造更好的技术条件**。

## 延伸思考

### 1. AI Agent 是"信任简化机制"还是"复杂性放大器"？

Luhmann 把信任定义为社会系统为应对复杂性而演化出来的简化机制。AI Agent 加入开源协作后，它是在**简化**复杂性还是**放大**复杂性？

- **简化**：Agent 自动测试、自动 review、自动文档，降低了人类参与治理的复杂度，让信任更容易建立
- **放大**：Agent 生成的贡献没有社会身份、没有声誉历史、没有长期博弈约束，人类**无法判断这个 Agent 可不可信**——这本身就是一种复杂性提升

Luhmann 的框架告诉我们：**这两种倾向并存**。真正的挑战是：**如何设计 Agent 治理机制，让 Agent 在开源协作中净效果是简化复杂性，而不是放大复杂性**——这是当前几乎所有 Agent 治理研究都还没回答的问题。

### 2. "开源社会契约"是不是 Luhmann 意义上的"信任简化机制"？

开源世界的"社会契约"——GPL / Apache License / Debian Social Contract / CONTRIBUTING.md / CODE_OF_CONDUCT / GOVERNANCE.md——这些文件是不是 Luhmann 意义上的"信任简化机制"？

- **GPL** 简化的是"你能怎么用我的代码"的不确定性
- **CONTRIBUTING.md** 简化的是"我要怎么贡献"的不确定性
- **CODE_OF_CONDUCT** 简化的是"社区边界在哪里"的不确定性
- **GOVERNANCE.md** 简化的是"谁有决策权"的不确定性

**开源治理的所有成文规则，本质上都是 Luhmann 意义上的"复杂性简化装置"**——不是"制造信任"（信任不能被制造），是让原有的信任机制能够更高效地运行。这个视角给"治理制品"这个概念提供了系统论的合法性基础。

### 3. "行政命令"的悖论：越是努力，越是失败

Luhmann 的洞见有一个更激进的推论：**行政动员式开源不仅无法产生信任，它越是努力，越是破坏信任**。因为它每一次"加强"（更多指标、更多考核、更多审查）都在系统论意义上**加速信任向服从的降格**——不是"效果不好"，是**努力本身就是破坏**。

这对开源治理的政策含义是极端的：**面对信任问题，最有效的干预可能是"少干预"**——不是"用更好的设计让行政动员产生信任"（这不可能），而是"停止把信任问题当行政问题来处理"。这一命题在制度经济学层面是极其不受欢迎的，因为它意味着**放弃行政力量对开源的介入**——但它给出了 Luhmann 系统论给出的最一致的答案。

### 4. 「开源四层制度基础设施」与 Luhmann 的复杂性简化

「开源四层制度基础设施」框架（代码托管 / 包镜像 / 开发工具 / 合规审计）可以被 Luhmann 视角重新读解为**四层"复杂性简化装置"**：

- **代码托管**简化的是"代码在哪里、谁能改"的复杂性
- **包镜像**简化的是"依赖从哪里来、版本怎么固定"的复杂性
- **开发工具**简化的是"我要装什么、我要怎么跑"的复杂性
- **合规审计**简化的是"我用的代码是否合规"的复杂性

**如果这是真的，那"开源四层制度基础设施"这个框架本身就是一个 Luhmann 意义上的信任简化图谱**——它不是"基础设施的清单"，是"社会复杂性被折叠进哪些制度装置"的地图。这个视角给「开源四层制度基础设施」框架补上了一层系统论的合法性基础。

## 金句

> "Trust is a functional mechanism that simplifies social complexity. It is not a moral virtue nor a psychological state, but an institutional arrangement that allows action under conditions of uncertainty."
>
> "信任是一种简化社会复杂性的功能性机制。它不是道德美德、不是心理状态，而是让行动能够在不确定条件下发生的制度安排。"
>
> "Trust cannot be commanded. If someone is commanded to trust, then what they are doing is no longer trust."
>
> "信任不能被命令。如果一个人被命令去信任，那么他正在做的事情就已经不再是信任。"
>
> —— Niklas Luhmann, *Trust and Power* (1979)
